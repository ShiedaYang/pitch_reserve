# Pitch Reserve · 本地场地监测

支持 Windows 与 Linux 的单用户控制台：四个普通租场入口、三组账号自动登录、手动接管、只读库存观察与官网跳转。**自动锁位未实现，程序不选中可订场次、不加购物篮、不提交预约或付款。**

需要 Node.js 24+。Windows 默认使用已安装的 Microsoft Edge；Linux 安装及远程人工接管参见 [Linux 部署说明](docs/linux-deployment.md)。Windows 首次安装并启动：

```powershell
npm install --cache .local/npm-cache
npm start
```

打开 <http://127.0.0.1:4318>。Windows 也可运行 `./start.ps1`，Linux 使用 `sh start.sh`；两端调用同一启动逻辑。默认只绑定127.0.0.1；Windows 用 `./start.ps1 -Lan`、Linux 用 `sh start.sh --lan` 或两端共用 `npm start -- --lan` 可显式开启局域网访问，启动时会显示访问地址，且只接受本机及允许的私有网段。前台运行时按Ctrl+C正常保存退出；后台运行时可用 Windows 的 `./stop.ps1` 或 Linux 的 `sh stop.sh` 正常关闭（支持自定义端口）。退出运行进程会停止监测；电脑睡眠期间无法检查。

启动会检查实际浏览器运行环境；缺少浏览器或依赖时先退出并给出修复命令，不进入循环重试。Linux 出现 `Executable doesn't exist` 时，以运行服务的同一用户在项目目录执行 `npx playwright install --with-deps chromium` 后重启；浏览器版本和缓存路径必须与当前项目一致，详见部署说明。

## 登录与恢复

1. 展开对应网站的“账号密码自动登录”，输入账号和密码，点击“保存并自动登录”。GGCB、Tower Hamlets独立；PlayFootball两场地共用一组。也可以点击“手动接管”直接在官网登录。
2. Windows 账号密码使用 DPAPI CurrentUser、Linux 使用 AES-256-GCM 加密保存在`.local/credentials/`，重启后可点击“使用已保存账号登录”。Windows 没有独立密钥文件；Linux 使用服务数据目录的 secrets/master.key（权限600）或环境密钥。更换系统时需要重新保存凭据。点击“清除账号密码”删除本机密文及运行内存中的凭据，不会退出已有官网会话。请勿把`.local/`分享给他人。

保存后，网站卡片直接显示账号明文和“密码：••••••••（已保存）”；展开表单会自动填入保存的账号。圆点是固定长度的状态占位符，不是真实密码。刷新页面仍会显示，正在修改的账号不会被轮询覆盖；清除凭据后账号及密码占位提示一并消失。继续登录可点“使用已保存账号登录”，修改密码则在密码框输入新值并保存。
3. 人工接管后1分钟没有官网或控制台操作，系统会自动检测会话并尝试恢复只读监测，无需点“恢复监测”。验证码、登录失败或未补齐资料时保留人工接管，每分钟最多检查一次；完成后空闲即可自动继续。主动点击“暂停”会保持暂停。页面轮询不算用户操作，计时只记录真实交互时间、不读取输入内容。浏览器启动串行执行，避免多个账号冷启动时争用；普通请求超时先关闭出错标签页并重开一次；再次超时提示“请手动接管”。识别人机验证时保留验证页并停止自动刷新，验证消失且日历恢复后空闲一分钟自动继续。其他临时异常约一分钟后重试，健康状态仍使用已配置的扫描间隔。
4. 日历、场地入口及通知中的“打开官网”是普通网页链接，在访问控制台的用户浏览器新标签页打开，不启动服务器浏览器，也不暂停监测。官网登录与结算在该用户浏览器完成，后台扫描账号的会话不会转移给用户。账号管理中的“手动接管”仍是本地管理员操作，用于维护扫描会话。

Council卡片的“场地表单默认选项”显示本机保存的场地、开放时间、居民/队伍类别、更衣室、Third、Senior及队名。自动扫描或登录恢复后会把这些明确保存的值填入官网，并通过普通Next进入日历；也可手动点击“应用默认选项并进入日历”。未保存地址默认值时不填写地址；不会自动确认条款，准备步骤到达日历即停止填表，随后只读扫描日历；需要补充个人资料或未确认条款时停下交人工。默认值存于本地SQLite，正常重启保留。

用户明确提供邮编后，可在`.local/council-address-defaults.json`保留默认邮编及官网地址选项标识。应用默认选项时使用官网查询，只有唯一有效地址或此前明确保存的选项才会选择；多个地址不猜选，查询失败不会套用旧邮编结果。不保存完整地址文本，不修改手动地址内容；该本机文件同样被Git忽略。地址选好后仅通过普通Next进入日历，不点时间或Confirm。

会话、加密凭据、SQLite和npm缓存存于`.local/`，已排除Git。检测到登录成功或正常关闭时保存官网会话；登录失效时最多尝试一次保留账号的自动登录。账号错误、验证码或安全验证会交回人工，不循环重试；验证码在官网输入。控制台API只返回已保存账号及保存状态，不返回密码；密码不存入浏览器localStorage/sessionStorage，不记录密码、验证码或银行卡，也不保存完整登录后页面HTML或网络请求。Windows 下只有当前用户可以解密 DPAPI 凭据；以同一用户身份运行的软件仍属于同一信任边界。Windows 默认使用已安装的 Edge，Linux 默认使用 Playwright Chromium；如需其他已安装通道，可设置`PITCH_BROWSER_CHANNEL=chrome`。

“账号与接管”每组网站提供“重启浏览器”：先关闭该组专属 Playwright 浏览器进程，再使用原 profile 重新打开官网；保留已保存账号与会话数据，不清除通知。PlayFootball 两个场地共用同一浏览器，一起重启。重启中防止重复操作；暂停状态保留，自动监测状态恢复，出现验证码或加载异常则交人工。不会关闭其他账号组或用户自己的浏览器。

## 当前范围和限制

PlayFootball 在工具窗口反复要求人机验证、普通浏览器可以正常进入时，可在“账号与接管”点击“普通浏览器验证”。程序先保存并关闭该网站的 Playwright 浏览器，再用同一专用 profile 打开普通 Edge/Chrome/Chromium；人工验证阶段没有自动化或调试连接。手动验证并确认进入日历后，关闭这个专用窗口，工具空闲检测会自动接回只读监测；不需要点恢复。窗口打开期间不扫描、不抢占 profile，服务重启也会保留等待状态。主动暂停仍保持暂停。此通道不能保证官网接受接回后的自动化：如果再次验证，会重新停下并保留“暂无信息”，不反复刷新或自动解题。

浏览器 profile 中的新 Cookie 优先于旧会话快照，过期 Cookie 和旧快照中的 Cloudflare 验证 Cookie 不会重新注入；人工通过后首次读取直接复用已验证的日历。Windows 默认使用同一安装的 Edge；Linux 人工验证需要图形桌面和 DISPLAY，可用 `PITCH_BROWSER_EXECUTABLE` 显式配置浏览器路径（普通验证与自动扫描使用同一可执行文件）。不要在验证过程中反复重启浏览器。

- 日期每天按伦敦当地明天自动顺延，默认查从明天起往后2个日历月；“监测偏好”可选往后1周、2周、1个月、2个月或3个月，保留10–120分钟检查间隔，默认15分钟。起止日期自动计算，无需每日保存或重启；跨午夜后自动监测网站会立即安排新范围检查，手动接管与主动暂停状态仍保留。旧版固定日期设置自动迁移为2个月，原检查间隔保留。月份按同日计算，月末无同日时取目标月最后一天。范围增加不代表官网已开放远期库存，未确认的日期仍显示“暂无信息”。
- GGCB半场55分钟、Stepney三分之一场、Westferry普通5v5产品85、Poplar普通7v7产品88。只读版本不创建订单，每周最多一场的偏好已展示，但不宣称能阻止用户在官网手动另订。
- PlayFootball解析可见日历、明确的日期表头和18:00时间块，按目标范围尝试正常下一周按钮；到达官网边界后保留未确认状态，不推算库存。“Available nearby”不计为本场可订。每个可选场次读取其时长与英镑价格。 两场地共用操作节奏：自动打开页面、登录面板、账号/密码填写、登录提交、关闭重开及翻周，每一步完成后至少间隔10秒再执行下一步；失败后重试也保留间隔。暂停或人工接管会取消等待中的旧操作，手动浏览不受限，其他网站速度不变。降低操作频率不能保证官网不再要求人机验证。
- GGCB按官网当前“下个月提前7天开放”规则标记未放号日期，不强翻未开放月份。月份请求失败时有界重载一次；等待对应日期请求及遮罩结束后读取时段，避免旧数据。只点日期，不点时间块和Book now；价格通过官网只读费用试算取得，不生成订单。
- Council已在用户登录、填写真实资格和联系资料后验证Stepney Green Third日历。只点击日期、Back和Earlier/Later；读取18:00的明确状态，不点击时间或Confirm。日期上的UNAVAILABLE不推断为已满，仍标注原因未明。
- Council目前未选择场次来核实实际租期及成交报价；如可见时段行展示唯一英镑金额则读取，否则明确显示价格待核实，不能用公开居民/非居民价猜测。页面的20分钟提示是表单时限，不能当作锁位证据。会话恢复后自动使用已保存的资格、队名及明确指定的地址选项准备日历；缺失的个人资料不猜填。日历尚未显示、未放号或无法查询时显示“暂无信息”，不推断为不可订，并继续自动监测。
- 点击可选场次通过用户浏览器打开固定场馆入口，不请求后台浏览器导航，也不会选择时间或保留库存。日期、时间和结算价仍需人工在官网确认。旧观察会标记需重新查验。
- 日期未开放、导航失败和页面结构变化不会显示为售罄。部分覆盖是可见状态；并非已证明扫描完两个月。
- “可订”是页面观察，无库存保留和成交价格保证；GGCB55分钟需用户确认偏好。当前不接受任何自动锁位设置。

## 通知列表与发送接口

“通知列表”页签显示发现时间、场地、日期、价格、发送状态及官网链接，支持查看更早记录。飞书配置位于“通知列表 → 飞书通知配置”，支持多个用户或群组收件人；可对待发送或失败记录点击“手动发送／手动重试”，无需开启自动通知；启用自动通知并保存后才会自动处理队列。手动操作只发送指定记录给已保存且勾选的收件人，跳过已有回执的收件人，保留库存新鲜度、有效期与送达不确定性检查。

- SQLite 中的 `notification_slots` 保存可订阶段，`notifications` 是独立持久化发件箱，不随最近400条扫描记录或运行日志的清理而删除。扫描结果与新通知在同一事务内提交。
- 唯一范围为“场地 + 日期 + 18:00 + 本次可订阶段”。持续可订、报价更新、重复扫描及重启不会重复入队；明确不可订后重新出现会创建新的通知。页面报错、缺失记录和未确认不会被当作一次消失。临时缩短再恢复日期范围也不创建重复阶段；新扫描确认后恢复原未发通知，已发送记录不重发。
- 尚未尝试发送的通知随最新观察更新价格和时长；首次发送尝试后固定消息内容和报价，以便幂等重试及保留准确历史。场次已不可订、超出监测范围或已过开场时间时，未发记录保留在列表中并标记已取消或已过期。
- 状态为 `PENDING / PROCESSING / FAILED / SENT / CANCELLED / EXPIRED / REVIEW_REQUIRED`。发送器使用原子领取、带令牌的租约、失败退避重试和送达确认；进程中断后可在租约到期时恢复。过旧观察须等新的扫描确认后才可发送。

只读列表接口：`GET /api/notifications?limit=50&before=<nextCursor>&status=PENDING`。`limit` 为1–100，`before`与`status`可省略；返回 `items`、`nextCursor`、全队列 `summary`、是否已有渠道配置的 `deliveryConfigured`，以及各收件人的送达记录。发送适配接口仍是 [src/notifications.ts](src/notifications.ts) 的 `NotificationSender`；飞书实现位于 [src/feishu.ts](src/feishu.ts)，自动通知开启后每5秒处理一个有界批次，不改变网站扫描间隔。

重试使用由通知ID和收件人派生的固定UUID，已确认送达的用户或群组不会重发。消息内容在首次尝试时固定。飞书UUID去重窗口为1小时，无法确认的请求在55分钟安全边界后会转为“需核对送达”，不再盲目重发；用户可核对飞书实际消息，再选择“已核实送达”或“已核实未送达，允许重试”。这避免把远端成功、本地未确认直接当作失败。两次轮询之间短暂出现又消失的空位仍受扫描间隔限制。参见[飞书官方SDK的UUID说明](https://pkg.go.dev/github.com/larksuite/oapi-sdk-go/v3/service/im/v1#CreateMessageReqBodyBuilder.Uuid)。

### 飞书配置与消息格式

采用与参考 `feishu_client.py` 相同的企业自建应用鉴权和 IM 消息接口，只保留发给用户、发给群组的能力。App ID在控制台显示；App Secret只以隐藏提示表示“已保存”，不会回传到前端。配置按当前系统使用 DPAPI 或 AES-256-GCM 加密保存在`.local/integrations/feishu.json`，不写入Git或浏览器存储。首次从用户提供的参考文件导入时保持自动发送关闭，不继承其他项目的启用开关。

控制台可添加 Open ID、User ID、Union ID、用户邮箱和群组 Chat ID，最多10个收件人。群聊需先加入应用机器人；用户需在应用可用范围内，并开通发送消息所需权限。“验证应用凭据”只获取应用Token，不发送消息，也不代表所有收件人的权限均已验证。Token会在服务端缓存，明确鉴权拒绝时可有界刷新，网络或业务错误不会把密钥、Token或原始响应写入日志。

消息使用富文本 `post`，包括日期、星期、伦敦当地起止时间、场地与规格、观察价格（缺失时待核实），并以“点击链接查看”链接到固定官网入口。消息不宣称库存已锁定，最终价格仍以官网为准。参见[官方消息内容格式](https://open.feishu.cn/document/server-docs/im-v1/message-content-description/create_json)。

配置接口为 `GET/POST /api/feishu/settings`；POST支持空密钥保留同一App ID的已保存密钥，更换App ID必须提交新密钥。`POST /api/feishu/send`以`notificationId`手动发送单条有效通知（自动通知可关闭）；`POST /api/feishu/validate`只验证凭据；`POST /api/feishu/reconcile`保存用户对特定收件人送达结果的明确核对，参数为`notificationId`、`targetKey`、`decision:delivered|retry`。所有POST沿用控制台CSRF和来源保护。没有任意文本消息发送接口。

排查发送失败时，`99992361`明确表示收件人的Open ID不属于当前应用。同一个用户在不同应用中的Open ID不同；必须在当前App ID对应的应用下重新获取，不能只换App ID和Secret后继续沿用另一应用的Open ID。控制台会把此错误显示在对应通知的历史失败记录中。验证按钮只验证当前应用凭据，返回明确的`credentialsValid`和`recipientDeliveryVerified`标志；历史拒绝会作为警告保留，不能伪装成本次实时验证失败，也不会阻断重新验证或手动重试。收件人能否接收须以实际投递回执为准。参见[飞书通用错误码说明](https://open.feishu.cn/document/server-docs/api-call-guide/generic-error-code)。


当前为单用户、回环绑定服务，已提供 Windows/Linux 浏览器选择、凭据与飞书配置加密、可配置数据目录及代理来源。部署、远程人工验证和密钥迁移参见 [Linux 部署说明](docs/linux-deployment.md)。本次没有部署远程服务器或新增多用户登录体系。

### 管理员故障通知与手动重发

飞书配置中的“管理员故障通知”有独立开关与用户/群组列表，不要求开启场次自动通知。反复超时、人机验证、扫描异常及场次投递失败会记录持久故障；同一网站同类故障持续期间只通知一次，恢复后重新发生建立新记录。管理员投递保留逐收件人回执、退避和固定UUID，超过安全去重窗口的未知送达会停止重试。通知内容只包含模块、时间、固定问题摘要和处理建议，不含凭据或个人地址。管理员通知自身失败只在控制台展示，避免递归告警。

已发送记录可点“重新发送”，接口为 `POST /api/feishu/send`，参数 `notificationId`、`resend:true`、`requestId:<UUID>`。显式重发保留原已发送记录，并创建新的投递及回执；相同 requestId 不重复发送，失败重试复用尚未完成的重发任务并跳过已送达收件人。不自动重发历史记录；消息明确标为历史观察，允许重发已经过期的原通知供人工查看，不宣称现在仍可订。

```powershell
node scripts/verify-console.ts
```

`PITCH_START_PAUSED=1`可让服务启动时先暂停所有供应商，用于本地界面与API测试。`PORT`可调整本地端口。

代码分为持久化浏览器会话、三个网站适配器、监测调度、SQLite和静态网页。API只开放固定供应商的登录/打开/检测/恢复/暂停/扫描、只读表单结构检查及正常关闭操作，以Host/Origin和启动令牌保护修改请求。结构检查不读取密码或输入值，不保存完整页面。没有通用浏览器操作或任意URL接口。网站适配器与操作节流代码在服务启动时加载；更新代码后需正常重启服务使其生效，本地保存的账号与会话数据保留。

## Ubuntu 远程浏览器与故障记录

无桌面服务器需要手动登录或验证时，使用 `sh start-desktop.sh` 启动虚拟桌面和有界面浏览器，再从“账号与接管”打开远程浏览器。首次需要安装桌面组件并设置 VNC 密码，详见 [Linux 部署说明](docs/linux-deployment.md)。原 `sh start.sh` 继续支持无界面监测。

运行记录可按级别与网站筛选、翻页，保存最近 5000 条；服务端 `PITCH_DATA_DIR/logs`（默认 `.local/logs`）另外保留 14 天逐日运行日志，包含启动故障、监测阶段、覆盖与价格计数、错误原因和恢复建议。Windows/Linux 使用同一记录机制。
